# Kepil — гражданская экоплатформа Каспия

Проект для Caspian Hackathon 2026. Веб-приложение геймификации экоактивности: жители репортят проблемы (мусор, нефть, браконьерство/редкие виды), получают баллы, обменивают на награды у партнёров, соревнуются в рейтинге городов/команд.

Этот файл — контекст для Claude Code. Полная тех.спецификация — в `docs/Kepil_tech_spec.docx`, бизнес-план — в `docs/Kepil_business_plan.docx`. Прочитай оба перед началом работы, если они есть в репозитории.

## Стек

* Frontend: React + Vite + Tailwind CSS
* Карта: Leaflet + OpenStreetMap (без платных API-ключей)
* Backend/БД/Auth/Storage: Supabase (Postgres)
* AI: LLM API для чат-бота и текстовой классификации, CV-модель/API для проверки фото
* Деплой: Vercel (frontend), Supabase Cloud (backend)

## Как работать с этим репозиторием

* Пиши код инкрементально по этапам ниже — не пытайся сделать всё за один проход.
* После каждого этапа — рабочее состояние, которое можно запустить (`npm run dev`).
* Все тексты интерфейса — на русском (можно добавить казахский позже, не блокирует MVP).
* Используй тестовые/демо-данные (см. `Этап 7`), чтобы карта и рейтинг не были пустыми.
* Не хардкодь API-ключи в код — используй `.env` (добавь `.env.example` с плейсхолдерами).
* Схема БД — точно по разделу 3 тех.спецификации. Если что-то не помещается в MVP — сначала спроси, не придумывай самостоятельно новые сущности.

## Этапы сборки

### Этап 1 — инфраструктура

* Инициализировать React + Vite проект, Tailwind
* Создать проект Supabase, настроить Auth (email/password)
* Создать таблицы по разделу 3 тех.спецификации (`users`, `teams`, `reports`, `events`, `event_participants`, `partners`, `rewards`, `redemptions`, `volunteer_raiders`, `badges`, `user_badges`)
* Включить Row Level Security на всех таблицах
* Настроить деплой на Vercel, подключить переменные окружения

### Этап 2 — репорты и карта

* Форма создания репорта: фото (со сжатием на клиенте), категория (`litter`/`oil`/`wildlife`), геолокация (авто через браузер + ручная корректировка на карте), описание
* Загрузка фото в Supabase Storage
* Публичная карта на Leaflet с маркерами репортов, фильтр по категории/статусу
* Лента последних репортов на главной

### Этап 3 — геймификация

* Начисление баллов по таблице весов из раздела 4 тех.спецификации
* Профиль пользователя: баллы, уровень, история репортов, значки
* Рейтинг: топ пользователей и топ команд/городов (переключатель вкладок)
* Логика значков (badges) — простые критерии (например, «10 репортов» → значок)

### Этап 4 — награды и партнёры

* Публичный каталог наград с фильтром по городу
* Обмен баллов на награду → списание баллов + генерация promo_code
* Упрощённый кабинет партнёра: список своих наград, CRUD (можно без сложного UI)

### Этап 5 — акции (еженедельные уборки)

* Список акций (официальные и пользовательские), создание акции любым citizen
* Присоединение к акции, загрузка фото «до/после»
* Начисление баллов после подтверждения участия

### Этап 6 — AI-слой

* Edge Function `POST /ai/classify-photo`: вызывает CV-модель/API, возвращает `{ label, confidence }`; при низкой уверенности статус репорта — `pending_review`
* Edge Function `POST /ai/chat`: проксирует сообщение пользователя в LLM API с системным промптом о правилах платформы и помощи в оформлении репорта
* Плавающий чат-виджет на всех страницах

### Этап 7 — модерация, демо-данные, полировка

* Панель модерации: очередь `pending_review`, подтверждение/отклонение
* Наполнить БД демо-данными: 15–20 репортов по Актау с реальными координатами, 3–5 демо-партнёров/наград, 2–3 акции
* Проверить полный цикл: регистрация → репорт → баллы → рейтинг → обмен награды
* README с инструкцией запуска (см. `docs/Kepil_tech_spec.docx`, раздел 7)

## Что сознательно вне MVP (не реализуем, только упоминаем в презентации)

* Реальная интеграция с рыбной инспекцией/полицией (только UI-заглушка формы)
* Реальные партнёрские API для списания скидок (промокод достаточно)
* Полноценная ML-модель прогнозирования горячих точек (можно простая эвристика по частоте репортов в районе/за период)

## Важно про волонтёров-рейдеров

Платформа НЕ присваивает статус «понятого» — это делает инспекция/полиция на месте. В системе храним только готовность волонтёра и контакт (см. таблицу `volunteer_raiders` в тех.спецификации). Не реализовывай никакой логики, которая выдаёт официальный юридический статус внутри приложения.
