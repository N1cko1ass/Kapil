## 1. Описание проекта

### Проблема

Каспийское море — крупнейший в мире замкнутый водоём — сталкивается с загрязнением бытовыми и промышленными отходами, разливами нефти, браконьерством и сокращением популяций осетровых и каспийского тюленя. Экологический мониторинг слабо оцифрован, данные о нарушениях разрознены, а жители региона почти не вовлечены в их фиксацию и решение.

### Решение

**Kepil** — веб-платформа гражданского экомониторинга Каспия. Житель фотографирует проблему (мусор / нефтяное загрязнение / браконьерство), геометка и категория попадают на публичную карту, фото проверяет ИИ и модератор, за подтверждённый репорт начисляются баллы. Баллы обмениваются на награды от партнёров, города и пользователи соревнуются в рейтинге, а еженедельные акции по уборке вовлекают сообщество в постоянную активность — так разовое неравнодушие превращается в привычку.

### Целевая аудитория

- **Жители городов Каспия** (старт — Актау) — создают репорты, участвуют в акциях, получают баллы и награды.
- **Модераторы / экоинспекция / акимат** — проверяют репорты, видят карту горячих точек в реальном времени.
- **Локальный бизнес** — партнёры каталога наград, получают приток клиентов и PR за счёт CSR.
- **Волонтёры-рейдеры** — регистрируют готовность участвовать в рейдах против браконьерства (координация, без присвоения юридического статуса — платформа только уведомляет инспекцию).

### Ожидаемый экологический эффект

Более быстрое обнаружение и устранение свалок и разливов за счёт распределённого гражданского мониторинга; накопление открытых геоданных о горячих точках загрязнения для планирования патрулей и уборок; рост вовлечённости населения благодаря игровой механике (баллы, уровни, значки, рейтинг городов).

### Основные функции

| Модуль | Функционал |
|---|---|
| Карта и репорты | Фото со сжатием на клиенте, геолокация (авто/ручная), категории (мусор/нефть/браконьерство), публичная карта на Leaflet без авторизации |
| ИИ-слой | Автоматическая проверка фото (Google Gemini, vision) — при высокой уверенности репорт подтверждается автоматически, при низкой — уходит модератору; чат-бот-помощник на всех страницах |
| Геймификация | Баллы по весу категории, уровни, значки за прогресс, рейтинг пользователей и команд/городов |
| Награды | Каталог наград от партнёров с фильтром по городу, атомарный обмен баллов на промокод |
| Акции | Создание и участие в уборках, подтверждение фото «до/после», бонус организатору |
| Партнёрский кабинет | Самостоятельная регистрация партнёра, CRUD своих наград |
| Модерация | Точечное подтверждение/отклонение репортов и участников акций для moderator/admin |

## 2. Технологии

| Слой | Технология | Назначение |
|---|---|---|
| Frontend | React 19 + Vite + Tailwind CSS 4 | SPA, адаптивная вёрстка |
| Карта | Leaflet + OpenStreetMap | Публичная карта репортов и акций, без платных API-ключей |
| Backend | Supabase (Postgres, Auth, Storage, Edge Functions) | БД, авторизация, хранение фото, серверная логика |
| ИИ | **Google Gemini API** (`gemini-flash-latest`, бесплатный тариф) | Проверка фото репортов (computer vision) и чат-бот-помощник |
| Иконки | lucide-react | UI-иконки |
| Деплой | Vercel (frontend) + Supabase Cloud (backend) | Хостинг, CI/CD из GitHub |

### Использование искусственного интеллекта

В проекте ИИ используется в двух местах и раскрывается открыто, как того требует ТЗ хакатона (п. 7):

1. **Классификация фото репортов** (`supabase/functions/classify-photo`) — фото отправляется в Google Gemini с промптом-инструкцией; модель возвращает категорию и уверенность в формате структурированного JSON. Логика принятия решения (порог уверенности, авто-подтверждение, откат к модерации) реализована самой командой на SQL-триггерах и Edge Function, а не моделью.
2. **Чат-бот-помощник** (`supabase/functions/chat`) — Google Gemini с системным промптом о правилах платформы, проксируется через собственную Edge Function, чтобы API-ключ не попадал на клиент.

Часть кода при разработке была написана с использованием ИИ-ассистента (Claude Code) как вспомогательного инструмента — в соответствии с п. 7 ТЗ команда понимает архитектуру решения, логику кода и готова объяснить любую часть реализации экспертной комиссии.

## 3. Архитектура

```
Браузер (React SPA)
   │
   ├─▶ Supabase Postgres — таблицы users/reports/events/rewards/… + RLS-политики
   ├─▶ Supabase Auth — email/password
   ├─▶ Supabase Storage — фото репортов и акций
   │
   └─▶ Supabase Edge Functions (Deno)
          ├─ classify-photo ──▶ Google Gemini API (vision)
          └─ chat ───────────▶ Google Gemini API (текст)
```

Начисление баллов, уровни и значки реализованы на стороне БД (SQL-триггеры на `reports`/`event_participants`), а не в клиентском коде — это исключает возможность накрутки баллов через консоль браузера.

Подробная схема БД — раздел 3 [docs/Kepil_tech_spec.docx](docs/Kepil_tech_spec.docx), бизнес-контекст — [docs/Kepil_business_plan.docx](docs/Kepil_business_plan.docx).

## 5. Установка и запуск

### 5.1. Supabase (БД, авторизация, хранилище)

1. Зайдите на [supabase.com](https://supabase.com) → **New project**.
2. Дождитесь инициализации, откройте **SQL Editor**.
3. По очереди выполните файлы из `supabase/migrations/` (по номерам, начиная с `0001`):
   - `0001_init.sql` — все таблицы, RLS-политики, Storage bucket `report-photos`.
   - `0002_user_profile_trigger.sql` — автосоздание профиля `public.users` при регистрации.
   - `0003_gamification.sql` — начисление баллов/уровней, значки.
   - `0004_rewards.sql` — атомарный обмен баллов на награду.
   - `0005_events.sql` — баллы за акции, Storage bucket `event-photos`.

   При наличии [Supabase CLI](https://supabase.com/docs/guides/cli) — альтернативно:
   ```bash
   supabase link --project-ref <ваш-project-ref>
   supabase db push
   ```
4. **Authentication → Providers → Email**: для ускорения тестирования отключите **Confirm email**, чтобы после регистрации сразу открывалась сессия.
5. **Project Settings → API**: скопируйте `Project URL` и `anon public` key.

### 5.2. Переменные окружения

```bash
cp .env.example .env
```

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

### 5.3. Установка и локальный запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`.

### 5.4. Проверка базового сценария

1. На главной открывается карта Актау без авторизации.
2. Регистрация (email/пароль/город) → создаётся профиль.
3. «+ Создать репорт» → фото, геолокация, категория, отправка.
4. Репорт появляется на карте и в ленте со статусом «На проверке».

### 5.5. ИИ-слой (классификация фото + чат-бот)

Обе Edge Function используют Google Gemini (`gemini-flash-latest`) — бесплатный тариф без привязки карты. Ключ не попадает на клиент: функции вызываются через `supabase.functions.invoke()`, запрос к Google делает сервер.

Деплой — через **веб-интерфейс Supabase Dashboard**, CLI не требуется:

1. Получите бесплатный ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
2. **Edge Functions → Deploy a new function → Via Editor**:
   - имя `chat` → код из [supabase/functions/chat/index.ts](supabase/functions/chat/index.ts) → **Deploy**;
   - имя `classify-photo` → код из [supabase/functions/classify-photo/index.ts](supabase/functions/classify-photo/index.ts) → **Deploy**.
   - ⚠️ Убедитесь, что итоговый URL функции заканчивается именно на `/chat` и `/classify-photo` — Dashboard иногда подставляет случайный слаг вместо введённого имени.
3. **Edge Functions → Secrets**: добавьте `GEMINI_API_KEY=AIza...`.
4. Проверка: репорт с фото получает `ai_label`/`ai_confidence` в таблице `reports` через несколько секунд; чат-виджет (кнопка внизу справа) отвечает на вопросы.

Без этого шага приложение работает штатно — фото просто не проверяются автоматически (остаются `pending_review`), а чат показывает сообщение об ошибке вместо ответа.

### 5.6. Деплой на Vercel

1. Импортируйте репозиторий на [vercel.com/new](https://vercel.com/new) (Framework preset — Vite, определится сам).
2. **Environment Variables**: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
3. Deploy.

Edge Functions на Vercel не деплоятся — см. п. 5.5.

## 7. Структура проекта

```
src/
  components/   переиспользуемые UI-компоненты (карта, навбар, карточка репорта, чат-виджет)

  hooks/        хуки загрузки данных (репорты и т.д.)

  pages/        страницы-роуты

  migrations/   SQL-схема, RLS-политики, геймификация (0001–0005)

docs/           тех.спецификация и бизнес-план хакатона (.docx)
```
